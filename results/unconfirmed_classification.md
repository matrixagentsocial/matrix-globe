## Rationale

- **trailing-zero decimal places** (spec_ambiguity): Specs say "at most 2 decimal places" with "10.005" as the example. They do not say whether "1.500" (numerically 2 places, written with 3) is valid; the reference reads it numerically, the reviewer reads the written form.
- **zero-quantized straight-line year** (spec_ambiguity): depreciation_straight_line rule 8 loops while the remaining base is > 0 charging min(raw, remaining); when the yearly amount quantizes to 0.00 the rules never terminate, so the spec does not define the result.
- **extra keys in an entry** (spec_ambiguity): prorata_billing rule 2: "Each entry is {date, monthly_price}"; it does not say whether extra keys are an "invalid entry shape".
- **duplicate rate keys** (spec_ambiguity): fx_triangulation does not say what happens when two rate keys normalise to the same code (other than EUR).
- **XIRR double root** (spec_ambiguity): xirr rule 11 says to raise when "no rate makes the NPV zero (no sign change ...)"; a double root makes the NPV zero without a sign change, so the two halves of the rule disagree.
- **large values / Decimal context precision** (shared_defect): Inputs are only required to be finite (apr_apy: "There is no upper bound"; allocate_ratios: weights "may have any number of decimal places"; weighted_average_cost uses precision 50 "for divisions"). The reference evaluates under Python's default 28-digit context (or rounds a multiplication at 50 digits), so huge or very precise valid inputs crash with InvalidOperation or lose cents.
- **trailing newline in dates** (shared_defect): Dates must be "exactly YYYY-MM-DD"; the reference uses a regex with "$", which also matches before a final "\n".
- **whitespace-only key or account** (shared_defect): idempotent_ledger rule 4: "key" and "account" must be "a non-empty string"; " " is non-empty, but the reference strips before checking.
- **unhashable movement type** (shared_defect): weighted_average_cost rule 2: "any other type raises ValueError"; the reference raises TypeError for a list.
- **non-ASCII digits** (shared_defect): The formats are fixed digit patterns ("any other format raises ValueError"); the reference uses \d, which also matches non-ASCII digits.
- **currency code checks** (shared_defect): fx_triangulation rules 3-4: codes are "exactly 3 letters A-Z" and "If EUR is present (in any letter case) its rate must equal 1"; the reference checks length after upper() ("ß" -> "SS") and lets a second spelling of EUR hide a non-1 rate.
